How a course works

Moving Parts makes complicated technical things understandable by taking them apart and rebuilding them. Each course follows the same rhythm:

  1. Read a little. Get the explanation needed for the next move.
  2. Manipulate the mechanism. Change inputs, inspect what happens and see what each part does.
  3. Build part of it. Recreate a meaningful piece in the form that suits the system.
  4. Assemble the real thing. Put the pieces together into something recognizably related to the system itself, not just an analogy.

No setup required

Everything needed for a course runs in the browser, with no account to create and nothing to install. When a course involves code, its language runtime runs in the page through WebAssembly and stays off the main thread. Your work is stored locally, and you can save it to a file and load it back. Every module is open from the start.

How these are made

I write and debug each course with one reader who does not know the topic. When they get lost, they tell me where, and I rebuild the passage around what went wrong. Each fix becomes a rule for the next course.

I publish those rules in the course kit, along with the process that produced them, the mistakes behind them, and the visual identity used here.
