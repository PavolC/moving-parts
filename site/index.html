What a course is

  • The code really runs. An editor in the page sends what you write to a real language runtime compiled to WebAssembly, off the main thread, so a training run never freezes the tab.
  • Nothing to install, and nothing to sign up for. No server, no account. The only thing that leaves your machine is the runtime download, once.
  • Your work lives in your browser. Editor contents, revealed hints and passed marks are stored locally, and every course can save them to a file and load them back.
  • Nothing is locked. Every module is open from the start. What finishing an exercise unlocks is the panel that runs on your own code, because there is nothing to run until the code exists.

How these are made

Each course is written against one reader who does not know the topic, which in practice means it is debugged rather than authored: the reader gets lost, says where, and the passage is rebuilt around what went wrong. Every such fix also leaves a rule behind, so the next course starts from the last one's failures rather than repeating them.

Those rules are extracted and public. The kit is the conventions with the topic taken out, the process that produced them, the incidents behind them, and this visual identity: the course kit.
